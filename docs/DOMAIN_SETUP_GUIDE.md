## Step 5 – Configure DNS

### What is DNS?

**DNS = Domain Name System**

Think of it like a phone book for the internet:
- You type: `appaammaspickles.com`
- DNS translates it to: `76.76.21.21` (an IP address)
- Your browser connects to that IP address

**Without DNS**, you'd have to remember IP addresses like `76.76.21.21` for every website.

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   You type  │────▶│  DNS Server │────▶│  IP Address │────▶│   Website   │
│ appaamma... │     │  "phone     │     │  76.76.21.21│     │   loads!    │
│  pickles.com│     │   book"     │     │             │     │             │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
```

### What are Nameservers?

**Nameservers** = The "authorities" that hold your DNS records.

When you registered with Cloudflare, your nameservers became:
```
ada.ns.cloudflare.com
bob.ns.cloudflare.com
```

This means: "Cloudflare is in charge of all DNS records for my domain."

### DNS Record Types Explained

#### A Record (Address Record)

**What:** Points a domain name to an IPv4 address (like `76.76.21.21`)

**Example:**
```
Type: A
Name: @ (means root domain - appaammaspickles.com)
Value: 76.76.21.21
TTL: Auto
```

**Use for:** Pointing your domain to your server's IP address.

```
appaammaspickles.com  ──A Record──▶  76.76.21.21 (Vercel's server)
```

#### AAAA Record (IPv6 Address Record)

**What:** Same as A Record but for IPv6 addresses (newer, longer format)

**Example:**
```
Type: AAAA
Name: @
Value: 2606:4700:3030::6815:1234
TTL: Auto
```

**Use for:** Supporting modern IPv6 connections (not always needed).

#### CNAME Record (Canonical Name)

**What:** Points a domain name to ANOTHER domain name (not an IP)

**Example:**
```
Type: CNAME
Name: www
Value: cname.vercel-dns.com
TTL: Auto
```

**Use for:** Subdomains like `www.appaammaspickles.com`

```
www.appaammaspickles.com  ──CNAME──▶  cname.vercel-dns.com  ──A──▶  76.76.21.21
```

**Important:** You CANNOT use CNAME for the root domain (`@`). Use A record instead.

#### TXT Record (Text Record)

**What:** Stores text information. Used for verification and email security.

**Example:**
```
Type: TXT
Name: @
Value: "v=spf1 include:_spf.google.com ~all"
TTL: Auto
```

**Use for:** 
- Domain ownership verification (Google, Vercel)
- Email security (SPF, DKIM, DMARC)

#### MX Record (Mail Exchange)

**What:** Tells email where to go. Points to mail servers.

**Example:**
```
Type: MX
Name: @
Value: mx1.emailprovider.com
Priority: 10
TTL: Auto
```

**Use for:** Receiving emails at `info@appaammaspickles.com`

```
Email to info@appaammaspickles.com  ──MX Record──▶  mx1.emailprovider.com (mail server)
```

**Priority:** Lower number = higher priority. If you have multiple mail servers:
- Priority 10: Primary mail server
- Priority 20: Backup mail server

#### NS Record (Nameserver Record)

**What:** Defines which nameservers are authoritative for your domain.

**Example:**
```
Type: NS
Name: @
Value: ada.ns.cloudflare.com
TTL: Auto
```

**Use for:** Already set by your registrar. Don't touch these unless transferring DNS.

### Email Security Records

#### SPF (Sender Policy Framework)

**What:** A TXT record that says "ONLY these servers can send email from my domain."

**Why:** Prevents spammers from sending fake emails pretending to be from your domain.

**Example:**
```
Type: TXT
Name: @
Value: "v=spf1 include:_spf.google.com include:zoho.com ~all"
TTL: Auto
```

**Breakdown:**
- `v=spf1` = This is an SPF record
- `include:_spf.google.com` = Google can send emails for us
- `~all` = Reject emails from everyone else

```
┌──────────────────────────────────────────────────────────┐
│  Someone receives email "from" info@appaammaspickles.com │
│                                                          │
│  Receiver checks SPF record:                             │
│  "Was this sent from an authorized server?"              │
│                                                          │
│  ✅ From Google servers → Deliver to inbox               │
│  ❌ From unknown server → Mark as spam/reject            │
└──────────────────────────────────────────────────────────┘
```

#### DKIM (DomainKeys Identified Mail)

**What:** A digital signature added to every email you send. Proves the email wasn't tampered with.

**Why:** Like a wax seal on a letter — proves it's authentic and unchanged.

**Example:**
```
Type: TXT
Name: google._domainkey
Value: "v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEB..." (long key)
TTL: Auto
```

```
┌─────────────┐    ┌─────────────────┐    ┌──────────────┐
│  You send   │───▶│  Email signed   │───▶│  Receiver    │
│  an email   │    │  with DKIM key  │    │  verifies    │
│             │    │  (like a wax    │    │  signature   │
│             │    │   seal)         │    │  ✅ Trusted! │
└─────────────┘    └─────────────────┘    └──────────────┘
```

#### DMARC (Domain-based Message Authentication)

**What:** A policy that tells receivers what to do if SPF or DKIM fails.

**Why:** You're saying "If an email fails authentication, here's what to do with it."

**Example:**
```
Type: TXT
Name: _dmarc
Value: "v=DMARC1; p=quarantine; rua=mailto:dmarc@appaammaspickles.com"
TTL: Auto
```

**Breakdown:**
- `v=DMARC1` = This is a DMARC record
- `p=quarantine` = If authentication fails, put it in spam
- `rua=mailto:...` = Send me reports about failed emails

**Policy options:**
- `p=none` = Do nothing (monitoring only) — START HERE
- `p=quarantine` = Send to spam
- `p=reject` = Block completely

### Complete DNS Architecture for Your Project

```
┌─────────────────────────────────────────────────────────────────┐
│                    appaammaspickles.com DNS                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  A     @              → 76.76.21.21 (Vercel)                     │
│  CNAME www            → cname.vercel-dns.com (Vercel)            │
│  A     api            → YOUR_BACKEND_IP (Spring Boot)            │
│  MX    @              → mail server (for email)                  │
│  TXT   @              → SPF record                               │
│  TXT   google._domainkey → DKIM record                          │
│  TXT   _dmarc         → DMARC policy                            │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘

Traffic Flow:
─────────────

appaammaspickles.com ────────────────▶ Vercel (Next.js Frontend)
www.appaammaspickles.com ────────────▶ Vercel (Next.js Frontend)
api.appaammaspickles.com ────────────▶ Your Server (Spring Boot Backend)
info@appaammaspickles.com ───────────▶ Email Provider (Google/Zoho)
```

### Part B: Add Custom Domain in Vercel

3. Click **"Domains"** in the left sidebar

5. Click **"Add"**
6. Vercel will ask how you want to configure it:

**Choose this configuration:**
```

7. Also add: `www.appaammaspickles.com`
8. Set `www` to redirect to the root domain (non-www)

### Part C: Configure DNS in Cloudflare

Vercel will show you the DNS records to add. Go to Cloudflare:

1. Cloudflare Dashboard → Select `appaammaspickles.com`
2. Go to **DNS** → **Records**
3. Add these records:

**Record 1: Root Domain (A Record)**
```

Name: @

```
Type: CNAME
Name: www
Target: cname.vercel-dns.com
Proxy Status: DNS Only (gray cloud) ← IMPORTANT!
TTL: Auto
```

> ⚠️ **IMPORTANT:** Set Proxy Status to **"DNS Only"** (gray cloud icon), NOT "Proxied" (orange cloud). Vercel needs direct DNS access for SSL to work.

- ✅ Valid Configuration

### Part F: DNS Propagation

DNS changes can take 1 minute to 48 hours to spread globally. Usually:
- Cloudflare: 1-5 minutes (fastest!)
- Other registrars: 1-24 hours

### Part C: Set Up Nginx (Reverse Proxy)

**What is a Reverse Proxy?**
Your Spring Boot runs on port 8080, but the internet talks on port 443 (HTTPS). Nginx sits in between:

```
Internet ──(port 443)──▶ Nginx ──(port 8080)──▶ Spring Boot
```

**Install Nginx on your server:**

```bash
# SSH into your server
ssh root@YOUR_SERVER_IP

# Install Nginx
sudo apt update
sudo apt install nginx -y

# Install Certbot (for SSL)
sudo apt install certbot python3-certbot-nginx -y
```

**Configure Nginx:**

```bash
sudo nano /etc/nginx/sites-available/api.appaammaspickles.com
```

**Paste this configuration:**

```nginx
server {
    listen 80;
    server_name api.appaammaspickles.com;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # WebSocket support (if needed)
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        
        # Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

**Enable the site:**

```bash
# Create symbolic link
sudo ln -s /etc/nginx/sites-available/api.appaammaspickles.com /etc/nginx/sites-enabled/

# Test configuration
sudo nginx -t

# Reload Nginx
sudo systemctl reload nginx
```

### Part E: CORS Configuration

**What is CORS?**
Cross-Origin Resource Sharing — allows your frontend (`appaammaspickles.com`) to talk to your backend (`api.appaammaspickles.com`).

**In your Spring Boot application**, add CORS configuration:

```java
// src/main/java/com/appaamma/pickles/config/CorsConfig.java

@Configuration
public class CorsConfig implements WebMvcConfigurer {
    
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
            .allowedOrigins(
                "https://appaammaspickles.com",
                "https://www.appaammaspickles.com"
            )
            .allowedMethods("GET", "POST", "PUT", "DELETE", "PATCH", "OPTIONS")
            .allowedHeaders("*")
            .allowCredentials(true)

    }
}
```

**Status:** Already enabled in Step 3! ✅

### 9.4 DNSSEC

**What:** Adds a layer of authentication to DNS. Prevents attackers from redirecting your domain to a fake server.

**How to enable on Cloudflare:**

1. Cloudflare Dashboard → Your domain
2. Go to **DNS** → **Settings**
3. Click **"Enable DNSSEC"**
4. Cloudflare handles everything automatically!

### 9.5 Cloudflare Security Features

Since your API goes through Cloudflare (proxied/orange cloud):

#### WAF (Web Application Firewall)
1. Cloudflare Dashboard → Security → WAF
2. Enable **Managed Rules** (free tier includes basic protection)
3. This blocks common attacks (SQL injection, XSS, etc.)

#### Bot Protection
1. Security → Bots
2. Enable **Bot Fight Mode** (free)
3. Blocks malicious bots from accessing your API

#### Rate Limiting
1. Security → WAF → Rate Limiting Rules
2. Create a rule:
   - URL: `api.appaammaspickles.com/*`
   - Rate: 100 requests per minute per IP
   - Action: Block for 60 seconds

**Example rule for login endpoint:**
```
URL: api.appaammaspickles.com/api/auth/login
Rate: 5 requests per minute per IP
Action: Block for 300 seconds (5 minutes)
```

### 9.6 Security Headers

server {

    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
